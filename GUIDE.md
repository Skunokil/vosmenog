# GUIDE — установка Воси (Vosmenog)

Пошаговая установка дисциплинированного агента. Базовый сценарий — **локальная
машина**; серверный (VPS) — в конце, надстройкой. Гайд обкатан вживую: грабли,
которые реально встречаются, помечены и обойдены.

> **Рабочая среда (проверено):** opencode-движок + **VSCode со встроенным терминалом**
> на компе, и **Termius** для доступа с телефона по SSH. Отдельный TUI-клиент opencode
> на практике не нужен — работаем через терминал VSCode.

---

## 0. Что ставим

Дисциплинированный агент-исполнитель для [opencode](https://opencode.ai). Четыре слоя:
- **METHOD** — метод работы (грузится всегда);
- **Vosmenog** — режим-исполнитель с урезанными правами (таб-переключаемый);
- **память + шаблоны** (эпик/задача/баг);
- **панель доверия** — TUI-плагин opencode: уровень доверия виден внизу экрана
  и переключается хоткеями (см. «Уровни доверия»).

Агент умеет читать страницы в интернете (webfetch) — для рекона документации
и примеров по ходу работы (см. «Веб-доступ»).

Нужен Unix-терминал: на Mac/Linux он родной, на Windows — через WSL.

---

## Шаг 0 — Linux (для Windows)

WSL — это настоящий Linux внутри Windows. В **PowerShell от администратора**:
```
wsl --install
```
Перезагрузись. После перезагрузки сам откроется терминал Ubuntu и попросит завести
пользователя.

> **Грабля:** имя пользователя — **только строчными буквами** (`skunokil`, не
> `Skunokil`), иначе Linux его отвергнет. Пароль печатается «вслепую» (символы не
> видны) — это нормально, набирай и жми Enter.

Дальше **все команды — в терминале Ubuntu**, не в PowerShell. Открыть Ubuntu потом:
Пуск → набрать `Ubuntu` → запустить (оранжевый значок).

**Mac/Linux:** терминал уже Unix, WSL не нужен — пропускай шаг 0.

## Шаг 2 — opencode

```
curl -fsSL https://opencode.ai/install | bash
```
Проверка версии:
```
opencode --version
```

> **Грабля (частая):** `--version` показывает **старую** версию или «command not
> found». Две причины:
> 1. shell ещё не подхватил новый путь → `source ~/.bashrc` и повтори, или закрой/
>    открой терминал заново.
> 2. **opencode уже стоял на Windows** (через npm) — тогда WSL подмешивает виндовый
>    PATH, и Linux зовёт старый виндовый бинарник. Диагностика:
>    ```
>    which -a opencode
>    ```
>    Если первым идёт путь `/mnt/c/...` — это виндовый. Поставь линуксовый вперёд:
>    ```
>    echo 'export PATH="$HOME/.opencode/bin:$PATH"' >> ~/.bashrc
>    source ~/.bashrc
>    opencode --version
>    ```
>    `which opencode` теперь должен указывать в `/home/...`, а версия — свежая.

## Шаг 5 — Периметр (безопасность)

Установщик спросит каталоги, которые агент **не должен трогать** (прод, секреты).
Это физический барьер — агент не дотянется, даже если захочет.

> **Грабля:** вводи **только пути**, через пробел, чистой строкой
> (`~/bot_factory ~/.ssh`). Не вставляй лишний текст — скрипт запишет его как есть.
> На чистой локалке закрывать нечего → нажми **Enter**, пропусти.

## Шаг 6 — Активация и проверка

```

```
В списке должен быть **Vosmenog (all)** с урезанными правами (опасные команды —

> убери `references` из `~/.config/opencode/opencode.json`.

## Уровни доверия — как пользоваться

После установки внизу экрана opencode (в режиме Vosmenog) видна **панель доверия** —
цветные прямоугольники `1 2 3`. Это ось доверия: сколько агент останавливается
и объясняет, прежде чем делать.

**Переключение:**
- `alt+1` / `alt+2` / `alt+3` — выбрать уровень (`ctrl+1/2/3` — запасной вариант);
- `alt+t` — свернуть/развернуть панель.

**Что означают уровни:**

| Уровень | Цвет | Поведение агента |
|---------|------|------------------|
| 1 — обучающий | зелёный | объясняет каждую команду до ввода; согласует всё, включая чтение |
| 2 — средний | жёлтый | свободно читает и реконит, согласует каждое изменение |
| 3 — продвинутый | красный | согласует только принципиальное (бэкап/откат) |

**Что НЕ меняется на любом уровне:** барьеры безопасности — прод и секреты закрыты
физически, `git push` и `sudo` под подтверждением, развилки агент не решает сам.

**Правило `min`:** проект может *ужесточить* уровень через слот в своём `AGENTS.md`
(см. ONBOARDING, раздел про доверие), но не ослабить. Нет слота — действует
выбранный в панели.

Выбор хранится в `~/.config/opencode/memory/user-profile.md` — панель пишет его туда.

## Веб-доступ (рекон по интернету)

Вося умеет загружать конкретные URL (`webfetch`) — читает документацию, примеры,
API по ходу рекона и отвечает по содержимому, со ссылкой на источник. Это сделано,
чтобы не догадываться «по памяти» о внешних инструментах.

- **Есть:** `webfetch` — загрузка конкретной страницы по адресу.
- **Нет:** `websearch` (поиск по интернету) — провайдер отдельной инфраструктуры,
  в комплект не входит. Нужен поиск — дай URL руками или скажи, что искать.

Веб-доступ — инструмент рекона, не автономного сёрфинга: агент читает страницы,
которые нужны ему для работы по ТЗ, и не ходит «просто посмотреть».

## Шаг 7 — Лаунчер проектов

`go` заводит проект и запускает opencode прямо в его папке (чтобы подхватились слоты
`<проект>/AGENTS.md`). Открой `~/.bashrc`, найди функцию `go`, добавь свой проект:
```bash
go() {
  case "$1" in
    myproj) cd ~/path/to/myproj && opencode ;;
    *) echo "go: неизвестный проект '$1'" ; return 1 ;;
  esac
}
```
`source ~/.bashrc` — и `go myproj` готов.

## Шаг 8 — Новый проект под Восю

1. В папке проекта создай `AGENTS.md` из шаблона
   `~/agent-os/project-slots.template.md`, заполни слоты (стек, пути, патч, билд,
   git-состояние, гейты). `AGENTS.md` — родной формат opencode, подхватывается сам.
2. Переключись на режим Vosmenog (Tab).
3. Цикл: **обсуждение → агент пишет EPIC → PBR → go → задачи → resolve.**
   Подробно — `~/agent-os/ONBOARDING.md`.

## Шаг 9 — Первый эпик (обкатка)

Возьми маленькую реальную задачу. В режиме Vosmenog опиши цель, обсудите развилки;
агент оформит EPIC (DoR/DoD/AC) — проверь, что развилки закрыты; дай go, агент
раздробит на задачи и исполнит под подтверждение; в конце — resolve.

## Шаг 10 — Настройка Минотавра (опционально)

Минотавр — это «голова»: архитектор и толкователь. Готовит варианты, разбирает
развилки, пишет тест-планы, делает PBR. Восьменог (Вося) — руки. Минотавр не
обязателен на старте; понадобится, когда задачи в зоне высокой неопределённости.

**Когда добавлять:**
- Задачи требуют архитектурных решений до кода
- Нужен внешний взгляд на ТЗ (PBR перед go)
- Проект растёт и появляется несколько параллельных эпиков

**Что нужно:**
- Проектное пространство в **Claude Projects** (claude.ai) или аналоге — например,
  **ChatGPT Custom GPT** (chatgpt.com), **Cursor** (правила/промпты проекта),
  любой другой чат-агент с возможностью загрузить файлы-инструкции (QA #11)
- Загрузить туда: `persona_minotaurus.md`, `head-workflow.md`, `dev-rules.md`,
  `session_start.md` (все из `~/agent-os/head-kit/`)

**Как подключить:**
1. Создай проект в Claude Projects (или аналог)
2. Загрузи файлы головы из `~/agent-os/head-kit/`
3. Скажи: «Ты — Минотавр. Читай session_start.md»
4. Готово — Минотавр доступен для PBR, разбора развилок, тест-планов

**Claude Code (CLI) как Минотавр:** если голова — это Claude Code на сервере, а не
чат Claude Projects — дай ему ссылку на самонастройку:

```text
прочитай ~/agent-os/CLAUDE_CODE_MINOTAUR.md и выполни самонастройку
```

Claude Code сам: проверит файлы фреймворка, создаст `~/.claude/CLAUDE.md` с роутером
(персона + воркфлоу + метод + обмен + доверие), стартует с уровнем доверия
«обучающий» (минимальный), научится `go <project>` и обмену с Восьменогом через
`team-work/<project>/exchange/{incoming,outgoing}`. Идемпотентно — можно повторять.
Проверка: `cat ~/.claude/CLAUDE.md`.

**Чужой агент на машине (любой):** онбординг, выбор персоны, где брать контекст —
`~/agent-os/FOREIGN_AGENTS.md`.

> **Два формата работы:**
> - **Пара** (Эпир + Восьменог) — для старта и простых задач
> - **Тройка** (Эпир + Восьменог + Минотавр) — для зоны неопределённости
>
> Подробнее — `~/agent-os/ONBOARDING.md`, раздел «Два формата работы».

## Карта сервера — правила вашей машины

Метод одинаков для всех, а машины разные: где лежит канал связи с владельцем, чего
нельзя в общем git-дереве, что агент делает сам, а что только владелец. Эти правила
живут не в методе, а в отдельном файле — **карте сервера**: `~/projects/team-work/SERVER.md`.

- `setup.sh` кладёт туда заготовку с названиями разделов; наполняешь ты, под свою машину.
  Файл уже есть — установщик его не трогает, ни при установке, ни при обновлении.
- Карта подключена в обе среды сама: в opencode строкой в `instructions`, в Claude Code
  импортом `@~/projects/team-work/SERVER.md` в `~/.claude/CLAUDE.md` (если Claude Code стоит).
  `update.sh` только **добавляет** эти строки, если их нет, и кладёт бэкап рядом.
- Любому агенту, не знающему сервера, достаточно сказать: «прочитай `SERVER.md`».
- Держи карту короткой (порядка 8 000 знаков): подробности и прецеденты — в архив, ссылкой.

## Два слоя: харнесс и Восьменог

Дистрибутив разделён на `harness/` (метод, единый вход, инструменты, адаптер Claude Code) и
`vosmenog/` (персона, агент и TUI для opencode, курс). `./setup.sh` ставит оба, как раньше.
`./setup.sh --harness-only` ставит только харнесс: без персоны Воси, агента opencode, TUI,
курсовых скиллов и лаунчера `go`. Режим запоминается меткой `~/agent-os/.harness-only`, и
`update.sh` его уважает. Из харнесса в `vosmenog/` ничего не ведёт: границу проверяет
`./check-boundary.sh` в корне репозитория.

---

## Единый вход для любого агента

Агенту, который не знает ни сервера, ни метода, хватает одной фразы: «Прочитай
`/home/<пользователь>/agent-os/BOOT.md` и работай по методу в проекте `<ключ>`». Путь давай
**абсолютный**: чужие агенты не раскрывают `~` и подставляют выдуманный `/home/user`. Файл отправляет его к команде
`evm boot <ключ>`, а та печатает порядок чтения (платформа, карта сервера, роль, проект,
смена) и текущую обстановку: входящее, незакоммиченное, соседние сессии. Роль задаётся
флагом `--role`; по умолчанию агент работает один во всех режимах. Установщики кладут
`BOOT.md`, `evm` и симлинк `~/.local/bin/evm`; если этого каталога нет в `PATH`, скрипт скажет.

## Установка и обновление: что именно происходит

Этот раздел отвечает на вопросы «что поставилось и куда», «обновление автоматическое или ручное», «что за команды появились и кто их запускает».
Читайте как справочник.

### Три места, не путайте

| Что | Где | Что это |
|---|---|---|
| **Клон репозитория** (источник) | там, куда вы сделали `git clone` (у владельца `~/projects/vosmenog`) | Единственное место, где метод правится и откуда обновляется. В нём лежат `setup.sh`, `update.sh`, `harness/`, `vosmenog/`, `CHANGELOG.md`. |
| **Установка** | `~/agent-os/`, `~/.config/opencode/`, `~/.local/bin/evm` | Только **копии** файлов из клона. Своего git нет. Править руками бессмысленно: следующее обновление затрёт. |
| **Ваши данные** | `~/projects/<проект>`, `~/projects/team-work/<проект>` (память смены, эпики), `~/projects/team-work/SERVER.md` | Установщик их создаёт только если их нет, и **никогда не перезаписывает**. |

### Что делает `./setup.sh` (установка, один раз)

Полная установка (без флагов) по порядку:

1. **Проверка среды** (нужен `python3`; наличие `opencode` — предупреждение, не ошибка).
2. **Каталоги и файлы метода** в `~/agent-os/`: `METHOD.md`, `BOOT.md`, шаблоны эпиков, задач и багов, `FOREIGN_AGENTS.md`, `ONBOARDING.md`, разделы метода `method/`, кит головы `head-kit/`, инструменты в `bin/` (`evm`, `projects-index.py`, `wt.sh`).
3. **Команда `evm`**: ссылка `~/.local/bin/evm` на `~/agent-os/bin/evm`. Если `~/.local/bin` не в `PATH`, скрипт скажет, что добавить.
4. **Восьменог для opencode** (`~/.config/opencode/`): агент `Vosmenog.md`, персона `~/agent-os/persona_vosya.md`, скиллы (`tutor`, `help`, `course-project`, `readiness`, `env-profile`, `server-audit`, `oom-guard`, `infra-bootstrap`), панель доверия, протокол старта `memory/STARTUP.md`, глобальные инструкции `AGENTS.md`. В `opencode.json` **добавляются** строки в `instructions` (чужие настройки не трогаются; копия `opencode.json.bak-...` рядом).
5. **Заготовка инфраструктурного проекта** `~/projects/infra` и `team-work/infra` — только если их ещё нет.
6. **Карта сервера** `~/projects/team-work/SERVER.md` — заготовка с названиями разделов; **наполняете вы**. Если файл есть, он не трогается. Подключается в opencode (строка в `instructions`).
7. **Адаптер Claude Code** — только если на машине есть `~/.claude`. Кладёт в `~/.claude/hooks/` два хука-обёртки (`session-start.sh`, `stop-guard.sh`) и `orchestrator.sh`, в `~/.claude/` панель `statusline.sh`, `statusline-tokens.py`; в `~/.claude/settings.json` **добавляет** блоки `SessionStart`, `Stop`, `statusLine` (чужие хуки и права не трогаются; копия `settings.json.bak-...` рядом); в `~/.claude/CLAUDE.md` дописывает строку импорта карты сервера. Нет Claude Code — шаг молча пропускается.
8. **Периметр прав Воси**: спрашивает, какие каталоги (прод, секреты) закрыть агенту.
9. **`~/.bashrc`**: лаунчер `go <проект>`, команда `vosya-update`, алиасы `wt` и `projects-index`. Блок добавляется один раз.
10. **Маркеры источника** (`~/.config/opencode/.vosmenog-source`, `.vosmenog-deployed`): по ним `vosya-update` находит клон, а проверка обновлений знает, что уже раскатано.

**`./setup.sh --harness-only`** делает то же, но **без** пунктов, относящихся к Восьменогу и opencode: нет персоны, агента `Vosmenog.md`, `opencode.json`, панели и курсовых скиллов, `AGENTS.md` для opencode, вопроса про периметр и лаунчера в `.bashrc`. Ставятся метод, `BOOT.md`, `evm`, карта сервера, кит головы, методические скиллы и (если есть `~/.claude`) адаптер Claude Code. В `~/agent-os/.harness-only` остаётся метка, и `update.sh` потом не «доустанавливает» Восьмино́га сам. Для машины, где работают другие агенты.

### Что делает `update.sh` / `vosya-update` (обновление)

Запускается **вами**, из любого каталога командой `vosya-update` (она находит клон по маркеру) или `./update.sh` в клоне.

1. Предупреждает, если в клоне есть **незакоммиченные правки** (они раскатаются на машину, но не уедут в репозиторий).
2. **`git pull --ff-only`** — тянет новое с GitHub. Если расходится — останавливается и просит разобраться, ничего не склеивая молча.
3. Печатает **«Что изменилось»** — список коммитов и файлов. Если сам `update.sh` обновился, перезапускается и доделывает новым.
4. **Раскладывает файлы заново**, как в `setup.sh`, но бережно: персона обновляется, только если вы её не правили (правили — скажет и не затрёт); периметр `deny` Воси переносится в новый агент; карта сервера и ваши проекты не затрагиваются; в `settings.json` и `opencode.json` **только добавляются** недостающие строки (с копией рядом).
5. Если в `~/.bashrc` осталась старая неработающая строка `alias vosya-update=…`, заменяет её на функцию (с копией `.bashrc.bak-...`).
6. Печатает **«Что нового (простыми словами)»** — верхнюю запись `CHANGELOG.md`, и напоминает: новые хуки и инструкции действуют **со следующей сессии**.

Чего `update.sh` **не делает никогда**: не трогает журналы и память смены, ваши проекты, `SERVER.md` (если он уже есть), ваши ручные правки персоны, чужие хуки и права.

### Автоматически или вручную

| Что | Как |
|---|---|
| Скачивание и установка обновления | **По умолчанию вручную**: `vosya-update`. Само не обновляется, по расписанию не ходит. Так задумано: обновление заменяет файлы, на которых работает агент, и вы должны видеть, что меняется. **По желанию автоматически**: `evm auto on`, см. ниже. |
| Проверка «вышло ли новое» | **Автоматически**, на старте сессии. Claude Code: хук запускает `evm boot`, в котором блок «Обновление метода». opencode: агент по протоколу старта. Проверка только спрашивает GitHub (`git fetch`) и сообщает. |
| Пересказ «что нового» | Автоматически: агент читает `CHANGELOG.md` и рассказывает вам по-человечески. Нераскатанное напоминается на каждом старте, пока вы не обновитесь; раскатанное — один раз **для каждого инструмента отдельно** (у Claude Code и у opencode свои отметки «показано»). |
| Хуки Claude Code (порядок чтения на старте, напоминание про память) | После обновления работают **сами**, с новой сессии. Подключаются `setup.sh`/`update.sh`; руками ничего включать не нужно. |

### Команды `evm`: что это, кто запускает, что делаете вы

`evm` — небольшая программа, которую ставит установщик. Она **ничего не меняет в ваших файлах**: читает состояние и печатает текст для человека и для агента.

| Команда | Что печатает | Кто запускает | Ваше участие |
|---|---|---|---|
| `evm boot [проект]` | Порядок чтения слоёв (метод → правила машины → роль → проект → память смены) с размерами файлов; **первое дело** из памяти прошлой смены; что лежит во входящих; соседние сессии; нет ли обновления метода. `--brief` — короткая форма. | **Claude Code: хук, само, на старте сессии.** opencode: агент, по инструкции, один раз за смену. | Никакого. Можно запустить самому, чтобы увидеть, что видит агент. |
| `evm close [проект]` | Чек-лист закрытия смены с ✓ и ✗: память обновлена после последней работы, не длиннее 4 000 знаков, есть строка о состоянии `HEAD`, есть подписанная строка в журнале, нет забытого незакоммиченного. | Агент в конце смены. | Можете запустить и увидеть красное сами. Ничего не записывает. |
| `evm threshold` | Только порог смены: время, соседние сессии, дерево, раскладка. | Входит в `evm boot`. | Не нужно. |
| `evm guard stop` | Служебная для хука `Stop` Claude Code. | Только хук. | Вручную не запускают. |

**Как агент «выполняет» команду:** у агента есть инструмент «запустить в терминале» (Bash). Хук Claude Code делает это за него до первого слова сессии и кладёт вывод в начало его контекста. В opencode в постоянных инструкциях Воси написано «в начале смены запусти `evm boot`», и он запускает её как любую другую команду. Для остальных агентов — фраза «Прочитай `/home/<вы>/agent-os/BOOT.md`» (там то же самое).

**Что видите вы.** В Claude Code вы ничего не печатаете: сессия открывается, и агент с первой реплики знает первое дело и обстановку. Единственное, что вы можете увидеть от сторожа Claude Code, — строка вида «evm: горячая память смены старше работы на N мин — агента попросили обновить её»: это значит, что агент сам допишет память и журнал.

### Автоматическое обновление (по желанию)

Включается командой `evm auto on` (или ответом «да» на вопрос установщика), выключается `evm auto off`, состояние — `evm auto status`. Файл настройки: `~/.config/vosmenog/auto-update`
(нет файла — выключено). Журнал: `~/.local/state/evm/auto-update.log`.

**Когда срабатывает.** На старте сессии (Claude Code — `evm boot` из хука; opencode — протокол старта) проверка обновлений видит, что на GitHub есть новое, и спрашивает «можно ли накатить само».
Само накатывается **только если выполнены все условия**:

| Условие | Зачем |
|---|---|
| Автообновление включено | Согласие пользователя; у тех, кто обновился со старой версии, оно выключено, пока не включите. |
| В каждой новой записи `CHANGELOG.md` (между вашей версией и свежей) стоит пометка `<!-- auto: ok -->` | Автор релиза этим утверждает: решений от пользователя не нужно, ничего не ломается. Релиз без записи или без пометки само не накатывается. |
| Клон репозитория чистый (нет незакоммиченных правок), стоит на ветке `main` | Иначе на машину уехали бы правки, которых нет в репозитории. |
| Обновление сводится простым «вперёд» (в клоне нет ваших коммитов) | Исключает слияния и конфликты. |
| Прошло не меньше 6 часов с прошлой попытки (`EVM_AUTO_INTERVAL_MIN`) и фоновое обновление не идёт | Не крутить обновление при каждом запуске сессии. |

Любое условие не выполнено — ничего не накатывается, вы видите обычное сообщение «вышло обновление, накати вручную» **с причиной**, по которой автоматика не сработала.

**Как оно выполняется.** `evm auto run` запускает `update.sh --auto` отдельным фоновым процессом (чтобы обновление не заменяло файл, который само исполняет) и сразу возвращает управление: старт сессии не ждёт.
Когда обновление закончилось, на следующем старте вы увидите «Метод обновился, вот что нового» с пересказом из `CHANGELOG.md`. Новые инструкции и хуки заработают со следующей сессии.

### Включение и выключение харнесса: что можно переключить и чего пока нельзя

Харнесс — это не одна программа, а несколько независимых подключений. Каждое включается и выключается по-своему.

| Что | Как включено | Как выключить | Переживёт ли обновление |
|---|---|---|---|
| **Весь харнесс сразу** | Хуки, подключения, проверка обновлений, автообновление. | **`evm off`** (постоянно, до `evm on`). Состояние: `evm status`. | **Да**: пока выключено, `update.sh` и `setup.sh` не возвращают ни хуки, ни строку карты, ни настройки. Файлы метода на диске всё равно обновляются. |
| **Метод в opencode** | Строки в `instructions` файла `~/.config/opencode/opencode.json` (протокол старта, метод, персона, карта сервера). | Удалить эти строки. | Строку карты сервера `update.sh` вернёт сам. Остальные вернёт только повторный `./setup.sh`. |
| **Карта сервера в Claude Code** | Строка `@…/team-work/SERVER.md` в `~/.claude/CLAUDE.md`. | Удалить строку (или обернуть путь в обратные кавычки, тогда это просто текст). | **Нет**: `update.sh` проверяет, что строка есть, и допишет, если её нет. |
| **Хуки Claude Code** (`SessionStart`: порядок чтения на старте; `Stop`: сторож памяти) | Блоки в `~/.claude/settings.json`, файлы в `~/.claude/hooks/`. | Всё сразу: `"disableAllHooks": true` в `settings.json`; на один запуск `claude --settings '{"disableAllHooks": true}'`. По одному хук без удаления отключить нельзя: Claude Code такого не умеет, только удалить блок. | `disableAllHooks` — **да** (установщик видит, что блоки на месте, и не трогает). Удалённый блок `update.sh` допишет заново. |
| **Панель внизу** (`statusLine`) | Ключ `statusLine` в `settings.json`. | `/statusline delete` в Claude Code или удалить ключ. `disableAllHooks` тоже её гасит. | Удалённый ключ `update.sh` допишет заново. |
| **Автообновление** | `~/.config/vosmenog/auto-update` = `on`. | `evm auto off`. | Да, это файл настройки, обновление его не трогает. |
| **Чувствительность сторожа памяти** | Порог 30 минут. | Не выключатель: `EVM_STALE_MIN=120` в окружении поднимает порог. | Да. |
| **Установка по частям** | `./setup.sh` или `./setup.sh --harness-only`. | Нельзя «отключить» Восьмино́га, поставленного раньше: нужно убрать его файлы вручную. | Метка `~/agent-os/.harness-only` удерживает режим «только харнесс» при обновлениях. |

**Предупреждение про `disableAllHooks`:** он гасит **все** хуки на машине, включая чужие — например, шлагбаум релиза (`release-gate.sh`) и отметку ПСИ. Если они у вас есть, выключать так опасно.

**Что произойдёт, если сломать или удалить `evm`.** По документации Claude Code хук с ненайденной командой даёт предупреждение, но сессия запускается; сам Claude Code не ломается.
Вы лишитесь только того, что делал хук (порядка чтения на старте и напоминания про память).

**Постоянный выключатель: `evm off` / `evm on` / `evm status`.** Файл-флаг `~/.config/vosmenog/harness-off`; пока он есть:
- хуки Claude Code (порядок чтения на старте, сторож памяти) молчат и ничего не делают;
- `evm boot` печатает одну строку «Харнесс выключен» (агент в opencode, получив её, работает как обычный агент);
- проверка обновлений и автообновление молчат;
- `update.sh` и `setup.sh` **не возвращают** хуки, строку карты сервера в `CLAUDE.md` и настройки (до этого удалённое возвращалось при каждом обновлении).

Чего `evm off` **не делает**: не удаляет файлы метода (они обновляются командой `vosya-update` как обычно, чтобы `evm on` включал уже свежее), не убирает строку `@…/SERVER.md` из `~/.claude/CLAUDE.md` и строки `instructions` из `opencode.json`
(это просто текст правил, его можно убрать руками), не отключает хуки, которые не принадлежат Vosmenog. `evm on` снимает флаг и сразу заново подключает хуки и карту сервера, если находит клон репозитория; хуки заработают со следующей сессии Claude Code.
Одна команда на разные случаи: `disableAllHooks` гасит вообще все хуки на машине, в том числе чужие (например шлагбаум релиза); `evm off` затрагивает только Vosmenog.
Полное удаление остаётся ручным: каталог `~/agent-os`, ссылка `~/.local/bin/evm`, блоки в `~/.claude/settings.json`, строка в `~/.claude/CLAUDE.md`, строки в `opencode.json`, блоки `go` и `vosya-update` в `~/.bashrc`, каталог `~/.config/opencode/memory`.

Каждый изменённый конфиг (`~/.claude/settings.json`, `~/.config/opencode/opencode.json`, `~/.bashrc`) `update.sh` и `setup.sh` сохраняют рядом как `*.bak-<дата-время>`. Откат — копирование этой копии на место. Хуки Claude Code отключаются удалением блоков `SessionStart` и `Stop` из `~/.claude/settings.json`. Метод целиком откатывается `git checkout <прежний коммит>` в клоне и повторным `update.sh`.

## Обновление

### Три уровня: где что живёт

```
GitHub (Skunokil/vosmenog)          ← источник истины, репо
      │  git clone (SSH)
      ▼
<источник>                           ← клон репо (у владельца: ~/projects/vosmenog)
      │  setup.sh / update.sh — запускаются ОТСЮДА
      │    раскладывают из <источник>/harness и <источник>/vosmenog:
      │      • METHOD.md, GUIDE, шаблоны, доки → ~/agent-os/ (копиями)
      │      • персона → ~/agent-os/ (не поверх ручной правки)
      │      • скиллы (tutor, readiness, env-profile, server-audit, oom-guard) → ~/.config/opencode/skills/
      │      • агент Vosmenog.md → ~/.config/opencode/agents/
      │      • STARTUP.md → ~/.config/opencode/memory/
      │      • TUI-плагины → ~/.config/opencode/plugins/
      │      • кит головы → ~/agent-os/head-kit/
      ▼
~/agent-os                           ← УСТАНОВКА: только копии, своего git нет
      ▼
~/.config/opencode/                  ← живой конфиг, из которого работает агент
```

> **Запомнить: `~/agent-os` — установка, а не репозиторий** (с 2026-09-09).
> Своего git у неё нет, она содержит только копии, разложенные `update.sh`.
> Разработка фреймворка идёт в **источнике** — клоне репозитория (на машине
> владельца это `~/projects/vosmenog`).
>
> Порядок всегда: правка в источнике → коммит и push → раскатка на машину.
> Обновление запускается **из источника**: `<источник>/update.sh`.
>
> **Правка руками прямо в `~/agent-os` не сохранится** — её затрёт ближайшая
> раскатка, и восстановить будет неоткуда: установка никуда не пушится.
> Раньше здесь лежал git-клон, и такая правка не терялась, а молча расходилась
> с дистрибутивом неделями — этот механизм снят вместе с `.git`.
>
> Сторожа два: `update.sh` перед раскаткой показывает незакоммиченные правки
> **источника** (раскатаются на машину, но не уедут в репозиторий), а агент
> проверяет то же самое при старте смены — `STARTUP.md`, раздел «В».

### Цикл изменений

1. **Правка** — в `harness/` (метод) или `vosmenog/` (персона и продукт opencode) клона репо (например, в рабочем клоне `~/projects/vosmenog`).
2. **Коммит + push** → в GitHub.
3. **Накатка агенту** — на сервере в `~/agent-os`: `git pull`, затем `vosya-update`
   (раскладывает дистрибутив в живой конфиг).

### Команды

**Накат метода (одной командой).** Когда захочешь обновиться:
```
vosya-update
```
Сам по себе `vosya-update` тянет свежий репо (git pull) и раскладывает **только
метод-контент** (METHOD, шаблоны, скиллы, кит головы, TUI-плагины). НЕ трогает
права/периметр Vosmenog, конфиг opencode и журнал — их меняешь осознанно.

**Уведомление (автоматически).** При запуске `go` раз в сутки тихо проверяется,
вышла ли новая версия в репозитории. Если да — увидишь:
`! Вышло обновление Vosmenog. Накати метод: vosya-update`. Сам накат не происходит —
машина не меняется без твоего решения.

**Полное обновление (включая конфиг/права).** Если поменялся `setup.sh`, права или
структура — нужен полный прогон **из источника**, а не из установки:
```
cd <источник>   # на машине владельца: ~/projects/vosmenog
git pull && ./setup.sh
```
На сервере он снова спросит периметр — введи свои прод-каталоги заново.

> **Почему так.** Автонакат конфига и прав на боевой сервер — это «код меняется без
> ведома владельца», ровно то, против чего весь фреймворк. Поэтому метод-текст
> обновляется легко, а барьеры периметра — только осознанно.

## Серверный сценарий (VPS)

То же самое, но opencode и проекты живут на сервере, а ты подключаешься: с компа —
VSCode «Remote-SSH», с телефона — Termius по SSH. Отличия от локалки:

1. **opencode на сервере уже есть** — шаг 2 пропускаешь.
2. **Периметр обязателен.** На сервере есть прод и секреты — закрой их наглухо.
   На шаге 5 вводи реальные пути, например: `~/bot_factory ~/.ssh`.
3. **Если на сервере была ручная/старая установка** — перед `setup.sh` сделай бэкап
   и убери устаревшее:
   ```
   cp -r ~/agent-os ~/agent-os.bak-$(date +%F) 2>/dev/null
   rm -f ~/agent-os/TZ.template.md      # старое имя шаблона
   ```
   `setup.sh` сольёт конфиг бережно (бэкапит, не задвоит instructions), память
   сохранит.
4. Установка: `git clone https://github.com/Skunokil/vosmenog.git && cd vosmenog &&
   ./setup.sh`, на периметре — пути прода, дальше как на локалке.

## Установка с ИИ-наставником

Не хочешь по шагам сам — кинь `INSTALL_PROMPT.md` первым сообщением в чат с
ассистентом, приложи папку комплекта, и он проведёт по этому гайду интерактивно.
