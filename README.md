# Vosmenog — фреймворк дисциплинированного агента для opencode


> **Студенту / ИИ-наставнику:** [**Начать ЭВМ 2.0 без установки → ENTRY.md**](ENTRY.md).
> **Что это:** открытый метод, который помогает людям и ИИ доводить дела до проверяемого результата, сохранять решения и продолжать работу без повторного объяснения всего сначала.
> **Как начать:** короткое знакомство с методом → одна настоящая задача → первый согласованный и проверяемый результат → при необходимости краткая память → продолжение. Не нужны Git, терминал или дополнительные агенты.
>
> **Статус:** EVM 2.0 пока представлен здесь **документальным учебным preview**; действующий Vosmenog ниже — отдельная реальная комплектация для разработки. Автоматический Composer, универсальные Agent Packs/адаптеры и ролевая оркестрация пока не реализованы.
>
> **Если используете Qwen, ChatGPT Project, Claude или уже установленного агента:** откройте [ENTRY.md](ENTRY.md) в этой же среде. Не начинайте с `INSTALL_PROMPT.md` — он предназначен для установки существующего Vosmenog. Если ИИ не смог прочитать репозиторий, приложите ENTRY.md как текст; не принимайте его догадки за проверенный метод.

Восилий (Vosmenog) — режим строгого исполнения для [opencode](https://opencode.ai):
агент-исполнитель по детальному ТЗ, который **не уходит в самодеятельность**.
Не архитектор, не трогает прод, документирует работу эпиками (DoR/DoD/AC), эскалирует
развилки вместо того, чтобы решать их догадкой.

## Что внутри

- **METHOD.md** — ядро метода (always-context).
- **agents/Vosmenog.md** — таб-режим с урезанными правами (барьер периметра).
- **EPIC / TASK / BUG** — шаблоны документирования.
- **STARTUP.md** — протокол памяти между сессиями.
- **setup.sh** — установщик (раскладка, конфиг, периметр, лаунчер).
- **skills/tutor** — обучающий режим: проводит новичка от «кто такой Вося» до живого рекона.
- **панель доверия** (TUI-плагин, `plugins/trust-panel.tsx`) — ось доверия видна
  внизу экрана, переключается `alt+1/2/3`, сворачивается `alt+t`.

## Способности

- **Веб-доступ (webfetch):** Вося загружает конкретные URL — документацию, примеры,
  API — для рекона по работе, отвечает по содержимому со ссылкой на источник.
  Поиска по интернету (websearch) в комплекте нет.
- **Уровни доверия:** три пресета (обучающий / средний / продвинутый) регулируют,
  сколько агент объясняет и согласует. Барьеры (прод, секреты, `git push`) стоят
  на всех уровнях. Подробно — `GUIDE.md`, разделы «Уровни доверия» и «Веб-доступ».

## Последние обновления

**2026-11-10 — Следующее действие по бэклогу и разовый GO на привилегированные команды.** Launcher проверяет совместимость правила до установки; при отказе существующая политика сохраняется. Метод просит любого агента найти ближайший шаг, выполнить уже согласованное в пределах задачи или вынести владельцу конкретное решение. Для Codex есть [запуск с подтверждением команд владельцем](harness/method/command-approval.md).

**2026-10-23 — метод работает под Windows (Git-bash).** Вылечены три «молчаливые» поломки: кириллица в выводе роняла скрипты (`UnicodeEncodeError`, cp1252), python находил WSL-овый `bash` вместо Git-bash и порог смены с проверкой обновлений молча пропадали, часть скриптов игнорировала `HOME`. Проверка обновлений больше не виснет на корпоративной сети (ограниченный по времени `git fetch`). Для установки под MSYS добавлен `windows-config/install-windows.sh`; на Linux и macOS поведение прежнее, действий не требуется.

**2026-10-12 (поздно вечером) — постоянный выключатель.** `evm off` выключает автоматику метода надолго (хуки, проверка и автообновление молчат, обновления не возвращают удалённое), `evm on` включает обратно, `evm status` показывает состояние.

**2026-10-12 (ночь) — каждый инструмент рассказывает об обновлении сам.** Если у вас и opencode, и Claude Code, оба по разу сообщат «Метод обновился»; раньше отметка была общая.

**2026-10-12 (вечер) — автоматическое обновление по желанию.** `evm auto on` включает: релиз, который автор пометил безопасным, накатится сам на старте сессии; остальное — вручную, `vosya-update`.

**2026-10-12 — метод стал «харнессом».** Любой ИИ-агент входит в метод одной фразой («Прочитай `…/agent-os/BOOT.md` и работай по методу в проекте X»).
Появилась команда `evm` (`evm boot` — с чего начать смену и что сейчас горит, `evm close` — чек-лист закрытия смены). В Claude Code два хука делают это
сами: кладут `evm boot` в начало сессии и один раз напоминают обновить память смены. Описан режим «один агент вместо пары». Правила вашей машины —
в одном файле `team-work/SERVER.md`. `./setup.sh --harness-only` ставит только метод, без Воси. Починена команда `vosya-update`.
Обновление по умолчанию ставится **вручную**, командой `vosya-update`; автоматику можно включить; обязательных действий нет.

## Установка действующего Vosmenog (необязательна для EVM 2.0 Preview)

```bash
git clone https://github.com/Skunokil/vosmenog.git
cd vosmenog
chmod +x setup.sh
./setup.sh
```

## Два слоя

Репозиторий состоит из двух слоёв, и ставятся они вместе (по умолчанию) или по отдельности:

- **`harness/` — действующий харнесс для разработки.** METHOD/BOOT, команда `evm`, шаблоны, память смены и адаптер Claude Code. Общие принципы есть, но инструменты, пути и установка пока имеют привязки к конкретным агентным средам. Это не универсальный runtime EVM 2.0.
- **`vosmenog/` — Восьменог.** Персона и продукт для opencode: агент, TUI-панель, учебный курс.

Для имеющейся установки без Восьменога есть `./setup.sh --harness-only`, но режим всё ещё использует некоторые каталоги и механизмы OpenCode/Claude Code. **Это не чистая универсальная установка EVM 2.0.** Для обучения без установки используйте [ENTRY.md](ENTRY.md).

Подробно, со всеми граблями — `GUIDE.md`. Для установки с ИИ-наставником — кинь
`INSTALL_PROMPT.md` первым сообщением в чат с ассистентом, приложив папку.

## Зачем это нужно

Дай агенту большую цель без точного задания — и он начнёт додумывать. Выберет
технологии за вас, полезет менять то, что трогать не просили, развернёт что-нибудь
на боевом сервере «чтобы работало». Не по злому умыслу — просто там, где нет
чёткого ТЗ, модель заполняет пустоту тем, что придумает сама. И обычные правила
в промпте («не трогай прод», «спрашивай перед важным») под нагрузкой забываются —
агент их прочитал, кивнул и всё равно сделал по-своему.

Vosmenog решает это не уговорами, а **устройством**:

- **Руки отняты, а не связаны просьбой.** Доступ к боевым каталогам и опасным
  командам закрыт на уровне движка opencode. Агент не «обещает не трогать прод» —
  он физически до него не дотянется.
- **Без задания — нет работы.** Голая цель «сделай Х» не запускает агента. Сначала
  оформляется документ (что делаем, как проверим, какие решения приняты) — и только
  потом код.
- **Развилки не решает молча.** Встретил выбор без ответа — останавливается и
  выносит человеку, а не угадывает.

Дисциплина держится конфигурацией и структурой, а не доброй волей модели. Поэтому
работает даже на слабых и быстрых моделях, которые обычные текстовые правила
игнорируют.
