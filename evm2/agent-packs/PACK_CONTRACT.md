# EVM 2.0 — Persona Pack contract v0.1 (D0.5)

> Документальная схема, одобрена для экспериментальной комплектации. Не универсальный runtime, не механизм выдачи полномочий.

## Разделение ответственности

- **Core** определяет метод: цель, результат, полномочия, свидетельства, проверка.
- **Project Adapter** вводит предметные правила, источники истины, ограничения и предпочтения.
- **Persona Pack** задаёт голос, устойчивый характер, специфику общения и список специализированных навыков.
- **Execution Binding** — реальная ChatGPT-сессия, CLI-агент или иной исполнитель с фактическими инструментами и правами.
- **Session Record** сохраняет идентичность работы, решения и диагностические свидетельства, включая переключения.

Персона не равна процессной роли и не делает модель отдельным агентом. Пак не отменяет требования действующего software-профиля об EPIC/TASK/PBR/GO.

## Состав и источник истины

Манифест — UTF-8 JSON pack.json. Минимальные поля:

| Поле | Назначение |
|---|---|
| schema_version | Версия формата, сейчас 0.1 |
| persona_id | Стабильный идентификатор внутри каталога |
| display_name | Отображаемое имя |
| visibility | public или private, с реальной проверкой доступности хранилища |
| lifecycle | documentary_preview / prepared_not_installed / tested / accepted |
| project_scope | Где можно предлагать профиль по умолчанию |
| persona_sources | Адреса канонической инструкции персоны |
| lore_sources | Необязательные адреса литературного лора; лор не равен правилам |
| skills | id + адрес исходника + статус доступности в runtime |
| authority | Указывает, что права не выдаются паком |
| activation, verification | Что реально реализовано и что проверено |

Ссылки на файл задаются объектом repository + path + ref. Рекомендуется закреплять commit SHA при воспроизводимом экспорте/установке. Относительный путь без репозитория разрешён только если текущий корень однозначно известен. Не выдумывать отсутствующий source и не копировать секреты в манифесты.

Манифест — **ссылка на источник**, а не дубликат лора или механизма памяти. Для отличающихся платформ допускаются отдельные адаптеры, но не несколько конкурирующих канонических персон.

## Навыки

У каждого skill есть id, source и availability. Значения, например:
- reference_only: файл прочитан, инструкции можно обсуждать;
- source_only: файл существует, но ещё не подключён;
- native_installed: конкретный runtime реально зарегистрировал навык;
- unavailable: нет доступа к исходнику или инструмента.

Не переносить механически OpenCode/CLI-модель прав в ChatGPT. Skill не создаёт доступа к сети, Git, shell и внешним API. Проверить наличие навыка, загрузку источника и выполнение задачи — отдельные проверки.

## Переключение

1. Определить область действия: текущая сессия, проект или явная передача отдельному агенту.
2. Приоритет: обязательные правила платформы и безопасность → проектные инструкции → действующий Core → согласованные предпочтения/активная персона → доступный pack.
3. Если есть явно установленная проектная персона, глобальная персона по умолчанию её не вытесняет.
4. Прочитать доступные канонические файлы выбранного пакета; проверить статус навыков и границы данных.
5. Явно обозначить логическое переключение **голоса и способа работы**, не обещая смену модели или запуск субагента.
6. Записать событие в прежний Session Record: from/to, why, available sources, expected/observed, source evidence, verification.
7. По запросу вернуться к предыдущему профилю без потери задачи. При невозможности загрузить pack — оставить прежний профиль и показать not_loaded.

Новый проект не обязан содержать каталог паков: достаточно ссылки на разрешённые источники и малого роутера. Если платформа не подгружает файлы автоматически, это инструкция пользователю/агенту, а не технический hook.

## Приватность и тест

- Публикация манифеста, его содержимого или узнаваемого лора разрешена только в контуре, определённом владельцем.
- Не копировать закрытые Project Files, конфигурации, переписки, персональные и чувствительные сведения в открытый каталог.
- Область действия навыка не шире Project Adapter; возможность инструмента не является GO.
- Положительный тест: явный выбор → чтение источника → ожидаемый голос и компетенция → возврат → та же сессия.
- Негативный тест: отсутствующий источник, недоступная персона, более строгие проектные правила, попытка расширить права. Ожидается отказ или безопасное уточнение.
- В наблюдаемости различать agent_reported, runtime_observed и externally_verified. Успешный ответ модели не доказывает, что платформенная настройка сохранена.

## Статус реализации

Схема и инструкции есть в Git. Автоматическая загрузка паков, переключение независимых runtime, универсальный Composer и веб-hooks **не реализованы** этой версией.
