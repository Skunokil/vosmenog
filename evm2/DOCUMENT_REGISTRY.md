# ЭВМ D0.4 — идентификаторы, адреса и индексация документов

> **Статус:** схема v1 + минимальный локальный индексатор. История существующих документов не переписывается. Единая кросс-платформенная база, облачная синхронизация и транзакционный allocator между серверами ещё не реализованы.

## Сессия предшествует любому EPIC

**Первый объект работы — Session Record.** Он создаётся при входе в сессию по методу с `classification=undecided` и пустым `work_refs`. На этапе исследования EPIC ещё не существует и не требуется. После квалификации сессия может остаться самостоятельным результатом (`research / one_off / no_epic`) либо породить EPIC, BUG, запись backlog или связаться с TASK действующего эпика.

Ссылка назад из созданного документа на исходную сессию обязательна; обратные ссылки хранятся в Session Record. Связи многие-ко-многим, без копирования событий или перезаписи идентичности. **Локальная команда `route` связывает только документы в одном каталоге planning**; при переходе из личного контура в новый проект двусторонние ссылки пока заносятся в соответствующие документы адресно и только в пределах прав. Автоматическая межпроектная синхронизация не реализована. Для native JSON сначала используй существующий механизм и не навязывай ему вторую Markdown-запись.

## Источник истины и владение документами

| Сущность | Каноническое место | Назначение |
|---|---|---|
| EPIC, TASK, ADR | `team-work/<project>/epics/` | Контракт, решения, критерии |
| BUG | `team-work/<project>/bugs/` | Причина/репро/проверка |
| Идеи и очередь | `team-work/<project>/backlog/` и ROADMAP | Не заменяется каталогом |
| Активная сессия Markdown | `team-work/<project>/sessions/active/` | Один живой Session Record |
| Закрытая сессия Markdown | `team-work/<project>/sessions/archive/` | Протокол завершённой работы |
| Native Codex-сессия | `team-work/<project>/sessions/work/*.json` | **Уже действующий** авторитетный JSON note engine; не создавать рядом вторую копию |
| Машинный каталог / обзор | `team-work/<project>/sessions/_catalog.json` / `_catalog.md` | Производные индексы, воссоздаются из источников |
| Горячая память | `sessions/next-session.md` | Только ближайший шаг и ссылки на документы |
| Семантический индекс | `sessions/_index.md` | Ручные подсказки поиска, не база идентичностей |

Не помещай сырые event logs, секреты или приватные разговоры в Git. Сессия может хранить ссылки на evidence из собственного контура; доступ к ним не следует из ссылки.

## Идентичность ≠ номер ≠ имя файла

- **`project_key`** — пространство имён (из паспорта проекта), например `demo`. Одинаковые `EPIC-001` в разных проектах не конфликтуют.
- **`doc_uid`** — устойчивый машинный идентификатор, **не меняется при переименовании или переезде**. Новый Markdown документ получает `D-` + 24 hex от генератора, не от догадки модели.
- **`code`** — читаемый человеком код в рамках проекта. EPIC: `EPIC-NNN`; TASK: `TASK-<номер EPIC>-<порядковый номер>` (например, `TASK-009-030`); BUG аналогично; ADR — по профилю проекта; сессия — `S-YYYYMMDDThhmmssZ-<12hex>`.
- **`path`** — местоположение, может измениться при контролируемом переезде. Ссылку между агентами передавай как `project_key + doc_uid + path`, а не только `TASK-009-30`.
- **`event_ref`** — `<session_uid>#E0001`: E-номер локален внутри сессии, не глобальная последовательность.
- **`work_ref`** — необязательная связь с созданным позже документом (по UID `D-...` или однозначному `path:epics/...` для legacy). До квалификации список пуст. Человеческий код допускается только как историческая ссылка, но не как новое разрешение неоднозначности.
- **`classification`** — `undecided` до исследования, затем `epic/task/bug/backlog/research/one_off/no_epic` (либо `mixed`, если из одной сессии вышли разные виды работ). История маршрутизации не равна решению о полномочиях.

Для нового Markdown-файла первая строка может содержать машиночитаемый комментарий:

```text
<!-- evm-doc: {"schema":1,"uid":"D-0123456789abcdef01234567","project":"demo","kind":"SESSION","code":"S-20261114T120000Z-abcdef012345","status":"active","classification":"undecided","route_history":[],"work_refs":[]} -->
```

Значение `uid` в примере **демонстрационное**, копировать его нельзя. Для создания новой Markdown-сессии используй установленную команду `evm-docs new-session`: она выдаёт уникальные реальные идентификаторы. В других средах получи UID через доступный безопасный генератор; если его нет, фиксируй подготовленную запись без притворства о сохранённом машинном ID.

## Legacy без опасной миграции

В существующем дереве есть дублирующиеся человеческие коды (`TASK-...` в нескольких именах файлов). **Не переименовывать, не объединять и не подменять** их при индексации. До явной миграции индексатор использует `legacy:<project>:<relative-path>` и ставит `identity=legacy_path_bound`; этот адрес меняется при переезде, поэтому нельзя выдавать его за долговременный UID.

Если один `code` соответствует нескольким файлам, `code` становится **неоднозначным псевдонимом**, а не идентификатором. Новые документы с таким кодом запрещены; существующие остаются со своими точными путями. Устранение каждого дубля требует отдельного решения, при необходимости redirects/aliases и обновления ссылок.

Существующие native JSON notes под `sessions/work/` уже используют устойчивый hash key и атомарную запись: индексатор регистрирует их **по имени**, не читая транскрипт, текст контракта или состояние. Это не миграция их схемы и не разрешение менять native gate.

## Индексатор и проверки

`~/agent-os/bin/evm-docs --planning /absolute/path --project demo <команда>`:

| Команда | Эффект |
|---|---|
| `scan` | Только чтение: число документов, коллизии кодов, ошибки UID |
| `check` | Проверка идентификаторов, дубликатов новых кодов, безопасности путей и свежести ранее построенного индекса |
| `index` | Явно пересобрать `sessions/_catalog.json` и `_catalog.md`; не трогать `_index.md`, ROADMAP, EPIC/TASK |
| `new-session` | Создать одну новую Markdown-сессию через `O_EXCL`; UID и код генерируются инструментом. Не вызывать для сессии, которой уже управляет native JSON engine |
| `new-work --kind EPIC/TASK/BUG --slug ... [--parent EPIC-NNN]` | Создать новый draft с UID и ближайшим свободным кодом под локальной блокировкой; не означает GO или готовность контракта |
| `route --session-uid D-... --kind ... [--work-path ...]` | После квалификации записать маршрут в активной сессии и историю решений; для работы требуется точный путь в том же planning-root. При переходе между разными контурами нужен отдельный адресный handoff. Меняет только метаданные сессии и производный каталог, **не выдаёт GO** |

Индексатор не публикует ничего в сеть, не выдаёт GO, не правит чужие документы, не берёт исходники приватных чатов и не считывает тело JSON-сессий. Каталог производный: если пропал, строится снова. Создание новых документов автоматически пересобирает каталог; если обновление индекса не удалось, возвращает статус `catalog=PENDING_REBUILD` и адрес созданного файла — повторять создание нельзя, нужно отдельно запустить `index`. Запись под локальным `flock` на каталоге `sessions/` (без мусорного lock-файла в Git) и через временный файл+`os.replace`; это защищает конкурирующих агентов **на одном файловом дереве**, но не разные Git-клоны/серверы. При параллельном Git merge требуется проверка кодов, UID и ссылок **до слияния**, иначе allocator по номеру не безопасен.

`check` отмечает старые коллизии предупреждением, не блокирует всю текущую работу. Если конфликт затрагивает новый документ с явным UID, это ошибка. При сохранении гипотез о проблеме используем отдельный Session Record; каталог не заменяет ретро.

## Правило записи и передач

1. Начать или возобновить **Session Record до EPIC**. Если проект ещё не определён, использовать собственный личный контур или переносимую запись. Не создавать дубликат уже существующего native JSON/Markdown источника.
2. Для нового Session Record выдать машинный UID, сохранить точный `path`, `code`, `classification=undecided`, пустые `work_refs`, `status=active`. Первоначальное намерение не выдавать за согласованный результат.
3. После квалификации определить маршрут и только при необходимости создать EPIC/BUG/другой документ; связать его по UID или точному legacy-пути с исходной сессией. Обновить каталог, проверить уникальность UID и связей. Индекс — свидетельство сохранения адреса, **не** приёмка результата.
4. При завершении переместить Session Record из `active` в `archive` без перезаписи; восстановить каталог, затем обновить `next-session.md` и краткую строку `journal.md`.
5. Передать следующему исполнителю `project_key/doc_uid/path`, текущий статус, evidence и `event_ref`. При недоступном сохранении пометить `prepared / not_saved`.

## AC для следующей реализации

- Сессия создаётся с `undecided` и без EPIC, затем маршрутизируется без смены UID; проверено на примере с `no_epic` и с созданием EPIC.
- Генерация идентификаторов с защитой от коллизий и атомарной записью проверена тестами, включая параллельный запуск.
- Дубли legacy TASK выявляются, но их файлы не меняются; новый повтор кода отклоняется.
- Индекс, удалённый пользователем, воссоздаётся побайтно без потери авторских документов.
- После переименования документа с настоящим `doc_uid` идентификатор остаётся прежним.
- Native JSON-сессия обнаруживается в каталоге без создания дубля или чтения её содержимого.
- `evm boot` при неоднозначном EPIC не выбирает случайный файл.
- Права, approvals, секреты, память и код Telegram-ботов не изменяются.
