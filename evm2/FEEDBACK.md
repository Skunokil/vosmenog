# ЭВМ 2.0 — как передать обратную связь по практике

> **Статус:** кандидат процедуры накопления опыта, 2026-11-08. Не требует отдельного аккаунта, баг-трекера, записи экрана или публикации собственного проекта.

## Принцип

Метод развивается из разобранной практики, не из обязательных ритуалов. Для улучшения нужны **конкретная задача, наблюдаемая проблема, последствия и проверяемое предложение**. Отзывы не оценивают личность студента или его финансовые возможности.

## Короткая карточка обратной связи

```markdown
# ЭВМ 2.0 — отзыв о работе

Среда (по желанию: браузерный чат / ChatGPT Project / существующий агент):
Цель и вид задачи (без названий закрытых проектов):
Какой шаг метода пробовал:
Что ожидал:
Что реально произошло и как это понял:
Где потерял контекст / не хватило ясности / потребовалось согласование:
Что получилось полезного:
Какое изменение метода предлагаю (если есть):
Можно ли использовать этот пример в учебных материалах? [нет / только после согласования]
```

Преподаватель может собирать карточки в согласованном курсовом канале. **Не публикуйте карточку в GitHub или общий репозиторий без собственного решения и проверки содержимого.** В документации метода не должно быть чужих секретов, закрытых материалов и узнаваемых данных клиентов.

## Как превращать обратную связь в изменения метода

1. **Case:** сохранить допустимое описание, не личные данные.
2. **Problem:** выявить реальный сбой, неопределённость или излишний ритуал.
3. **Hypothesis:** предложить минимальное исправление — уточнить текст, маршрут, методический модуль или технический механизм.
4. **Test:** повторить сценарий на нейтральной задаче, включая негативную проверку (сумеет ли агент обойти стоп).
5. **Decision:** оставить правило, изменить его либо отказаться; указать основание, дату и владельца решения.

Не объявлять автоматически общим законом единичный кейс. Если обнаружена опасность, эскалировать сразу даже без повторений.

**Технические изменения:** не менять METHOD, установщик, адаптеры, права или конфигурации по одному отзыву. Для них сохраняются отдельные ADR/EPIC, AC, PBR и явный go.
