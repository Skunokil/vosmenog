# Разовое подтверждение привилегированной команды

Агент готовит точную команду, хост, причину, эффект и способ проверки. Владелец
подтверждает конкретный запуск в интерфейсе исполнения. После подтверждения агент
выполняет команду и проверяет результат. На другой хост, изменённую команду или
повтор после ошибки нужно новое разрешение. В среде без такого интерфейса
останови привилегированное действие и передай владельцу вопрос о допуске.
Передавай привилегированную команду отдельным вызовом с видимыми аргументами.
Пакет shell-команд или скрипт под root требует отдельного согласования его содержимого.

## Codex CLI

После обновления харнесса запусти `~/agent-os/bin/evm-codex-go --install` от рабочего
пользователя. Скрипт устанавливает отдельное правило `evm-privileged.rules` в
каталоге правил Codex. Проверка `execpolicy check` должна показать `prompt`.
Проверочная команда при этом не выполняется.

Для новой интерактивной сессии запусти `~/agent-os/bin/evm-codex-go` из рабочего
каталога проекта. Скрипт запускает Codex в `read-only`, с `on-request` и
проверяющим `user`. Для перечисленных команд повышения привилегий Codex
запрашивает подтверждение на каждый вызов. Выбирай разовое подтверждение.
Действующую сессию нужно перезапустить, поскольку правила читаются на старте.

Проверка на целевом хосте: попроси агента выполнить `sudo -n -- true` с разовым
одобрением. Сначала отклони запрос и проверь, что команда не запустилась. Затем
одобри новый запрос. Если `sudo` сообщает, что требуется пароль, подтверждение
Codex сработало, а ОС требует отдельной аутентификации. Для режима без пароля
администратор может заранее разрешить конкретную команду с фиксированными
аргументами или отдельную обёртку, принадлежащую root, через `sudoers`. Скрипт не изменяет
`sudoers`. Для такой команды агент использует `sudo -n`.

Правило действует в Codex для перечисленных форм команд. Системный периметр
задают песочница, права рабочего пользователя и политика ОС. Для других сред
используй их интерфейс одобрения команд и правило метода о явном GO.
