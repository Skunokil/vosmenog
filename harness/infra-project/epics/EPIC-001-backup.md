## Зачем (vision-кусок)

Сервер — единственное рабочее место: проекты, базы данных, секреты, документация
и память агента. Эпик создаёт регулярную страховку всего рабочего состояния в S3,
чтобы потеря сервера превратилась из катастрофы в процедуру восстановления.

## Квалификация (вопросы для сбора требований)

| Вопрос | Ответ владельца |
|--------|-----------------|
| Кому нужно? | Владельцу сервера (единственная копия данных) |
| Какая ценность? | Потеря сервера = процедура восстановления, а не катастрофа |
| Границы | ВХОДИТ: БД (postgres-контейнеры), файлы проектов, конфиги, секреты, документация/память. НЕ входит: восстановление образа ОС |
| Edge cases | Испорченный дамп перезаписывает хороший (→ ротация); потеря пароля restic (→ пароль у владельца); креды S3 в git (→ .env в .gitignore) |
| Зависимости | S3-бакет, креды, установка restic, пароль restic |
| Формат приёмки | Тест восстановления (временная БД) + минимум 2 успешных cron-запуска |
| Приоритет | Высокий |

## AC — acceptance criteria

1. **Ежедневный бэкап БД:** скрипт дампит postgres-контейнеры через `pg_dump` и заливает в S3-репозиторий restic. Проверка: `restic snapshots` показывает снапшот за сегодня.
2. **Ежедневный бэкап файлов:** в тот же репозиторий уходят `~/projects/` (код, team-work, память), `~/.ssh/`, конфиги. Проверка: снапшот содержит перечисленные пути.
3. **Ротация:** хранятся последние N≥7 снапшотов, старые удаляются автоматически (`restic forget --keep-last N --group-by tags`). Проверка: после N+1 запусков ровно N.
4. **Шифрование:** репозиторий зашифрован паролем; пароль не хранится на сервере в открытом виде и не известен агенту. Проверка: пароль только в `~/projects/infra/.env` (chmod 600).
5. **Восстановление:** документированная процедура `restore` (restic restore → восстановление дампов → подъём БД). Проверка: тест восстановления прошёл (временная БД, сравнение количества таблиц).
6. **Креды не светятся:** `~/projects/infra/.env` в `.gitignore`; креды/пароль не появляются в git-истории, логах и чате. Проверка: `git grep -i` по репозиториям не находит ACCESS_KEY/SECRET.
7. **Cron зелёный:** задача ежедневная, в логах нет ошибок за 2+ суток подряд.
