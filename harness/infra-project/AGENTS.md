# AGENTS.md — Infra

> Инфраструктурный проект сервера: бэкапы, обслуживание, надпроектные работы.
> Периметр — весь сервер (в отличие от продуктовых проектов). Касание прода —
> только владелец, по явному go. Развёртывание — скилл `infra-bootstrap`.

## Что здесь

| Что | Где |
|-----|-----|
| Скрипты бэкапа | `~/projects/infra/` (репозиторий) |
| Креды restic/S3 | `~/projects/infra/.env` (chmod 600, в git НЕ попадает) |
| Планирование и эпики | `~/projects/team-work/infra/` |
| Память сессий | `~/projects/team-work/infra/sessions/` |

## Команды проекта

```bash
# Полный ежедневный бэкап (БД + файлы + ротация 14)
~/projects/infra/backup.sh

# Бэкап только БД / только файлов
~/projects/infra/backup-db.sh
sudo -n ~/projects/infra/backup-files.sh   # /etc от root

# Восстановление (см. RESTORE.md)
~/projects/infra/restore.sh list
~/projects/infra/restore.sh db
~/projects/infra/restore.sh db-apply       # ДЕСТРУКТИВНО — перезаливает БД
~/projects/infra/restore.sh files --target DIR

# Снапшоты / лог
cd ~/projects/infra && set -a && . ./.env && set +a && restic snapshots
tail -20 ~/projects/infra/backup.log
```

## Гейты

| Действие | Кто решает |
|----------|-----------|
| `.env` (креды, пароль restic) | Только владелец |
| Заливка БД из бэкапа на прод (`db-apply`) | Владелец (подтверждение скрипта) |
| Восстановление файлов поверх системы | Владелец |
| Изменение cron / скриптов бэкапа | Агент (в рамках EPIC), после go |
| Push репозитория infra на GitHub | Владелец |

## Секреты

- `.env` не читать значениями в чат, не выводить, не коммитить (`.gitignore` закрывает `.env*`).
- Пароль restic — у владельца в менеджере паролей. Потеря пароля = потеря бэкапа.
- Логи бэкапа могут содержать пути/ошибки — секреты туда не попадают.

## Наблюдения (уроки EPIC-001-backup)

- Спецсимволы (`&`, `$`, `#`) в значениях `.env` ломают `source` — значения всегда в кавычках.
- `RESTIC_REPOSITORY` для S3: `s3:хост/бакет` (слэш, НЕ двоеточие перед бакетом).
- Файловый бэкап `/etc` требует root (`sudo -n`), иначе ssh-ключи/sudoers/shadow не читаются.
- `restic forget` — с `--group-by tags`, иначе db-снапшоты с меняющимися временными путями не попадают в лимит.
- Тест восстановления — во временную тестовую БД, не в прод.
