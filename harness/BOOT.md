# BOOT.md — вход в метод ЭВМ для любого агента

Тебе сказали «прочитай этот файл и работай по методу в проекте `<ключ>`». Это вся
инструкция входа. Метод, правила машины и память смены лежат в других файлах:
здесь только порядок, в котором их читать, и две команды.

## Шаг 1. Одна команда

```bash
evm boot <ключ-проекта> [--role solo|head|hands|text]
```

Она ничего не меняет, только печатает: какие файлы читать по порядку (с размерами),
что лежит во входящих, кто работает рядом, что не закоммичено. Ключ — из
`~/projects/INDEX.md`; достаточно однозначного начала (`trans` для `transformatornaya`).
Команды нет в PATH — читай слои руками, порядок ниже тот же.

**Пути.** В этом файле и в других документах `~` - домашний каталог пользователя. Инструмент
чтения файлов тильду не раскрывает, а имя пользователя ты не знаешь: узнай `echo $HOME` и
подставляй абсолютный путь. `evm boot` печатает уже абсолютные.

## Шаг 2. Слои, по порядку

| # | Слой | Файл | Как читать |
|---|------|------|-----------|
| 1 | Платформа (метод) | `~/agent-os/METHOD.md` | стопы и эпик-цикл; глубже — по необходимости |
| 2 | Карта сервера | `~/projects/team-work/SERVER.md` | **целиком**: канал с владельцем, общее дерево, границы прода |
| 3 | Роль | см. ниже | по роли |
| 4 | Проект | `<проект>/AGENTS.md` | карта, гейты, ветки |
| 5 | Смена | `team-work/<проект>/sessions/next-session.md` | **целиком**; эпик — по ссылке из него |

`journal.md` и `archive/` целиком не читай, только грепом по адресу. Бюджет входа в
смену — 25 000 токенов; вылез — дефект документа, скажи владельцу.

## Роль

Роль задаётся в команде. Не задана — **`solo`**: ты один агент и по очереди работаешь
в трёх режимах: думаю (развилки, ТЗ, ревью), делаю (код и документы), проверяю (тесты,
аудит вывода). Персона не нужна; голос и стиль не обязательны, правила обязательны.

Уровень 1, команда персон, включается явно: `head` — голова (архитектура, развилки,
ревью), `hands` — руки (рекон и исполнение по готовому ТЗ), `text` — тексты. Файл
персоны покажет `evm boot`. Обмен между ними — каталоги `exchange/incoming` и `outgoing`.

## Шаг 3. Доложи и начни

Первой фразой назови владельцу первое дело из горячей памяти и что ты понял про
обстановку (соседние сессии, незакоммиченное). Нет документа — сначала документ
(правило 0 метода), потом работа. Развилку, которой нет в ТЗ, не угадывай: разложи
варианты владельцу.

## Чего `evm boot` не знает

- **Порог смены видит только сессии Claude Code** (по их сокетам). Сессии opencode и
  чужих агентов в списке соседей не появятся. «Ты один в работе» значит «одной
  Claude-сессии рядом нет», а не «никого нет».
- Нет хука порога на машине — соседей не видно вовсе, `evm boot` так и напишет.
- Он не проверяет, что файлы свежие, и не читает за тебя. Размеры нужны, чтобы
  оценить бюджет, а не чтобы пропускать слои.

## Конец смены

Перезапиши `next-session.md` (первое дело следующей смены, не хроника) и добавь одну
строку в `journal.md`, подписанную персоной или своим именем. Ритуал полностью —
`~/.config/opencode/memory/STARTUP.md`, раздел «Завершение сессии».
