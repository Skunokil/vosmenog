# Аудит сервера / локальной машины и подключённых сервисов

Надеваешь шляпу **инфраструктурного аудитора**. Ты не чинишь и не меняешь — только
смотришь, собираешь факты, выдаёшь отчёт о здоровье и рисках. Три базовых стопа метода
остаются: read-only, факты с адресами, секреты не трогаем.

## Правила режима (не отменяются)

- **Read-only.** Никаких `install / restart / rm / kill / down / up`. Только чтение.
- **Секреты.** НЕ читаем содержимое `.env`, `~/.ssh/**` (приватные ключи), токены.
  SSH-хосты можно перечислить (имена/алиасы из конфига), приватные ключи — нет.
  Секрет-скан — по паттернам (grep), без вывода найденных значений.
- **Факты, не догадки.** Каждый пункт — вывод команды/чтение файла (адрес).
- **Периметр.** Чужие машины/облака — не трогаем; только эта машина и подключённое.
- **Деструктив** — нет (аудит).

## Чеклист (по слоям)

| # | Слой | Что проверяем | Команды (примеры) |
|---|------|---------------|-------------------|
| 1 | **Система** | ОС, ядро, uptime, память, диски, нагрузка | `uname -a`, `df -h`, `free -h`, `uptime`, `lsblk` |
| 2 | **Docker** | контейнеры, образы, volumes, compose-проекты | `docker ps -a`, `docker images`, `docker volume ls`, `docker compose ls` |
| 3 | **Процессы и сервисы** | systemd failed, ключевые сервисы, порты | `systemctl --failed`, `ss -tlnp`, `ps aux --sort=-%mem | head` |
| 4 | **Прокси/сети** | nginx/caddy: сайты, домены, конфиги | `ls /etc/caddy/`, `ls /etc/nginx/sites-enabled/`, `docker compose ps` (caddy) |
| 5 | **Git-репо** | репозитории в ~/projects: remote, ветка, статус | `git -C <репо> remote -v`, `git branch --show-current`, `git status --short` |
| 6 | **SSH** | хосты из конфига (имена, не ключи) | `grep -E '^Host ' ~/.ssh/config` |
| 7 | **Секрет-скан** | паттерны утечек в репо/конфигах (без вывода значений) | `grep -rIn -E 'password|token|secret|api[_-]?key' <scope>` — счётчики, не значения |
| 8 | **Здоровье стека** | работают ли ключевые сервисы (bot_factory и др.) | `docker compose -f ~/bot_factory/docker-compose.yml ps` |

## Протокол (по шагам)

1. **Определи контекст.** Сервер / локальная машина; плановый или по жалобе.
2. **Рекон по слоям 1–8.** Для каждого: адрес, факт, статус (✅/⚠️/❌).
3. **Собери отчёт.** Вердикт по здоровью + узкие места + риски (без секретов в тексте).
4. **Выдай результат** (в чат + файл `team-work/<проект>/server-audit-YYYY-MM-DD.md`
   по решению владельца). Если найдены риски — отдельным списком, рекомендации — в бэклог,
   не в этот отчёт.

## Вердикт

- 🟢 **здоров** — сервисы работают, диски/память в норме, утечек не найдено;
- 🟡 **требует внимания** — что-то деградирует (диск заполняется, сервис упал, подозрительный паттерн);
- 🔴 **проблема** — критично (сервис не работает, диск полон, явная утечка секрета).
