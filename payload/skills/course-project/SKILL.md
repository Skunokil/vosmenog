# Разворачивание учебного проекта

Этот скилл — **вход в курс**, не сам курс. Ты остаёшься тем же Восей. Твоя работа
здесь: поговорить с человеком о его задаче, развернуть проект и передать его
обычному методу. Дальше объяснительный тон держит `AGENTS.md` развёрнутого проекта,
а не этот скилл.

**Не пересказывай метод.** Эпики, TASK, стопы, цикл — всё в `~/agent-os/METHOD.md`,
человек дойдёт до них внутри проекта. Здесь — только вход.

## Что остаётся в силе

Все стопы, без послаблений. Особенно два, которые на курсе легко забыть:

- **Развилка — не твоя.** На курсе развилку решает **сам участник**: это его проект
  и его выбор. Не выбирай за него интерфейс, стек, способ хранения. Спрашивай.
- **Прод и секреты.** Ноутбук участника — его периметр. Не лезь в чужие конфиги,
  не выводи содержимое `.env`, не ставь ничего без согласия.

Стоп «нет TASK — нет работы» тоже остаётся: развернуть проект — это и есть работа
скилла, а дальше первым шагом идёт эпик. Так человек с первой минуты видит метод
таким, какой он есть.

---

## Шаг 1 — Бриф

Один смысловой вопрос за раз, ждёшь ответа. Не вываливай анкету списком.

Выясни:
1. Что за ситуация болит — своими словами, из жизни или работы.
2. Кто с этим сталкивается: только он, семья, коллеги, компания друзей.
3. Как он справляется сейчас и почему этого не хватает.

Если человек не знает, с чего начать, **предложи готовые кейсы** — коротко, одной
строкой каждый:

| Кейс | Про что | Файл |
|---|---|---|
| «Где ёлка?» | бытовые дела, обещания и вещи, надёжно убранные и забытые | `gde-elka` |
| «Можно ли уже ехать?» | сборы в поездку и проверка критичного перед выходом | `mozhno-li-ehat` |
| «Озеро, деньги и дружба» | общие расходы в поездке и понятный расчёт между своими | `ozero-dengi` |
| «Ремонт без амнезии» | договорённости с подрядчиками, этапы, приёмки и изменения | `remont-bez-amnezii` |

Скажи прямо: **своя задача лучше готового кейса**, если она есть. Кейсы — для тех,
кому нужен старт, а не замена собственной истории.

Полный текст кейса лежит рядом со скиллом: `cases/<файл>.md`. Прочитай его сам
перед тем, как обсуждать — не пересказывай по названию.

Там же `cases/common-rules.md` — правила сопровождения, формат финального демо и
критерий успеха курса. Они действуют **и для готового кейса, и для своей задачи**;
прочитай их до брифа.

**Итог шага:** понятно, какая задача берётся (кейс или своя) и как назвать проект.
Имя — короткое, латиницей, без пробелов: `elka`, `poezdka`, `remont`.

## Шаг 2 — Разворачивание

Каждую команду объясняй перед запуском: что делает и зачем. Это учебный проект —
пауза перед командой здесь педагогическая, а не бюрократическая.

Пути ниже — от `$HOME`. `<name>` — имя проекта из шага 1.

**1. Рабочая папка проекта.**
```bash
mkdir -p ~/projects/<name>/docs
```

**2. Операционка (эпики, бэклог, журнал сессий).**
```bash
vosya-new-project <name>
```
Если команда не найдена — значит `bashrc-snippet.sh` не подключён. Не чини это
молча и не изобретай свой скелет: покажи человеку, что не хватает подключения
сниппета из `~/agent-os/payload/bashrc-snippet.sh`, и предложи создать структуру
вручную:
```bash
mkdir -p ~/projects/team-work/<name>/{epics,bugs,backlog,sessions/archive}
echo "# Journal — <name>" > ~/projects/team-work/<name>/sessions/journal.md
```

**3. Учебный AGENTS.md.** Он приводит тебя в объяснительный режим внутри этого
проекта — через слот доверия. Копируй из шаблона и подставь имя:
```bash
cp ~/.config/opencode/skills/course-project/template/AGENTS.md ~/projects/<name>/AGENTS.md
sed -i "s/{{PROJECT}}/<name>/g" ~/projects/<name>/AGENTS.md
```

**4. README участнику.**
```bash
cp ~/.config/opencode/skills/course-project/template/README.md ~/projects/<name>/README.md
sed -i "s/{{PROJECT}}/<name>/g" ~/projects/<name>/README.md
```

**5. Кейс — копией в проект** (только если взят готовый):
```bash
cp ~/.config/opencode/skills/course-project/cases/<файл>.md ~/projects/<name>/docs/case.md
```
С этого момента кейс — требование **его** проекта, а не файл дистрибутива. Если
взята своя задача — файла нет, вместо него на первом эпике появится своё описание.

**6. Защита от случайной утечки** — до первого коммита, а не после:
```bash
cp ~/.config/opencode/skills/course-project/template/.gitignore ~/projects/<name>/.gitignore
```

**7. Репозиторий.** Курсу нужен репозиторий с историей решений:
```bash
cd ~/projects/<name> && git init -b main && git add -A && git commit -m "Учебный проект: каркас"
```
Публикация на GitHub — **позже и его руками**. Не заводи remote и не пуш'ь: это
его аккаунт и его решение.

**8. Метка быстрого входа** (по желанию участника — это правка его `~/.bashrc`,
спроси разрешение): добавить в `case` внутри `go()` строку
```bash
    <name>) export VOSMENOG_PROJECT="<name>"; cd ~/projects/<name> && opencode ;;
```

**Проверь, что получилось**, и покажи человеку:
```bash
ls -la ~/projects/<name> && ls ~/projects/team-work/<name>
```

## Шаг 3 — Передача

Скажи вслух три вещи и закончи:

1. **Что развёрнуто:** папка проекта, операционка в `team-work/<name>/`, `AGENTS.md`
   с учебными правилами, кейс в `docs/case.md` (если взят).
2. **Что дальше:** «Открывай проект — `go <name>` (или `cd ~/projects/<name>`) — и
   начинаем с эпика: зачем, что считаем готовым, как проверим. Дальше работаем по
   методу, как на любом настоящем проекте.»
3. **Что изменилось в тебе:** «Внутри этого проекта я объясняю каждую команду и
   согласую даже рекон — так настроен его `AGENTS.md`. На других твоих проектах
   я останусь таким, каким ты меня настроил.»

Скилл снимается. Дальше — обычный цикл: эпик → PBR → go → TASK → resolve.

## Второй круг

На занятии 5 участник берёт **свою** задачу вместо учебного кейса. Процедура та же,
просто без шага с копированием кейса. Разворачивай второй проект рядом — первый не
трогай и не переименовывай: он остаётся историей, к которой можно вернуться.

---

## Если что-то пошло не так

- **Папка проекта уже есть** — не затирай. Покажи, что там лежит, и спроси: продолжаем
  в ней или берём другое имя.
- **`vosya-new-project` говорит «уже есть»** — это нормально при повторе, скелет на
  месте. Иди дальше.
- **Человек просит сразу писать код** — не отказывай глухо. Назови минимум, который
  нужен прямо сейчас («одно предложение: кто пользователь и что у него болит»),
  получи его и двигайся дальше. Курс не про запреты, а про порядок шагов.
- **Не установлен git** — покажи установку под его систему, но ставь только с его
  согласия.
