> Контракт фазы разработки. Агент формализует **итог обсуждения** с владельцем —
> не выдумывает решения, а записывает принятые и делает проверяемыми. Живёт в
> `team-work/<project>/epics/` проекта, растёт от старта к resolve. Удали этот блок в готовом файле.

## Зачем (vision-кусок)

Какую часть продукта двигает эпик. Связь с общим vision/целями — 2-3 предложения.
Если эпик уводит от текущего vision — это флаг на эскалацию, не замазывать.

## Квалификация (вопросы для сбора требований)

Перед оформлением эпика задай владельцу эти вопросы. Не все обязательны — но если
ответа нет, это дыра в ТЗ, которую нельзя закрыть догадкой.

| Вопрос | Зачем |
|--------|-------|
| **Кому это нужно?** (пользователь / разработчик / система) | Чтобы понять формат AC |
| **Какая ценность?** (что меняется для пользователя) | Чтобы связать с vision |
| **Границы изменений** (что входит, что НЕ входит) | Чтобы не раздуть эпик |
| **Edge cases** (что может пойти не так) | Чтобы заложить обработку |
| **Зависимости** (от чего блокируется, что блокирует) | Чтобы выстроить порядок |
| **Формат приёмки** (автотест / ручная / визуальная) | Чтобы написать AC |
| **Срок / приоритет** (срочно / можно подождать) | Чтобы расставить порядок |

> Если владелец не может ответить — это не стоп, а сигнал: нужен Минотавр для
> проработки или рекон текущего состояния.

## RESOLVE

> Заполняется по завершении. Хвост этого же файла.
>
> **Ретроспектива — обязательный этап.** Перед resolve остановись и проанализируй
> по трём направлениям: аудит кода, анализ треда, анализ поведения агента.
> Подробный процесс — в METHOD.md (раздел «Ретроспектива (resolve)»).
> Без ретроспективы resolve неполон.

### Чек-лист перед resolve

**Не закрывай эпик, пока хотя бы одна галочка не закрыта.** Пройдись по всем
чеклистам — ВСЕ пункты должны быть [x]:

- [ ] **DoR:** все пункты готовности выполнены
- [ ] **DoD:** все критерии завершённости закрыты
- [ ] **AC:** все acceptance criteria выполнены
- [ ] **Задачи:** все TASK/BUG в статусе done
- [ ] **Roadmap:** статус эпика обновлён (in progress → done / resolved)
- [ ] **Backlog:** проверены зависимости (новые задачи / отменённые / изменившие приоритет)

> Если какой-то пункт не закрыт — **не пиши resolve**. Разберись: либо задача
> не сделана (сделай), либо критерий неактуален (обнови с обоснованием),
> либо нужен BUG на пропущенное.

больше времени, чем ожидалось.
