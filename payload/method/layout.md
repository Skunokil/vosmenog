# METHOD → Проект на диске

Где лежат проекты, подпроекты, рабочие ветки и снимки — и кто их убирает.
Ядро (пять строк) — в `METHOD.md`, § «Проект на диске». Здесь — подробности.

> **Почему раздел появился** (EPIC-025 vosmenog, 2026-10-07). В методе было
> правило «релиз и черри-пик — через `git worktree`», и ни слова о том, где
> worktree лежит и кто его снимает. За три недели на одном сервере выросло
> 14 рабочих веток в корне `~/projects` и в `/tmp` (12 давно влиты), каталог
> планирования уехал в `~` под симлинк, два реестра проектов разошлись.
> Ни одна сессия не была небрежной: каждая выбирала ближайшее место, потому что
> другого правила не было. **Механика без места и срока даёт ровно такой результат.**

## 1. Дерево

```
~/projects/
  INDEX.md                 ← генерирует projects-index.py, руками не правится
  <проект>/                ← свой git, паспорт в AGENTS.md
    <подпроект>/           ← вложенный git, исключён в .gitignore родителя
      .worktrees/<ветка>/
    .worktrees/<ветка>/    ← рабочие ветки — только здесь
  team-work/
    <проект>/              ← планирование; закрытое — свой git, исключён в team-work
  _archive/                ← сироты и замороженное, с датой в имени
~/backups/                 ← снимки и бэкапы с датой в имени
```

В корне `~` — только установка и инфраструктура (`agent-os`, `projects`,
`bot_factory`, `backups`, `deploy`). Всё остальное — нарушение, которое
`projects-index.py` покажет на пороге смены.

## 2. Проект и подпроект

- **Проект** — каталог верхнего уровня в `~/projects/` со своим git и паспортом.
- **Подпроект** — часть проекта, ведётся отдельным репозиторием (плагин, сервис,
  микросервис). Лежит **внутри** родителя: `~/projects/alfa/apl/`. В
  `.gitignore` родителя — строка `/apl/`. Правила родителя (AGENTS.md)
  действуют и для подпроекта; свой AGENTS.md подпроекта их уточняет.
- Планирование подпроекта — подкаталог планирования родителя:
  `team-work/alfa/apl/`, не отдельный проект в team-work.
- **Новый проект или подпроект — только с паспортом.** Создал каталог — первым
  коммитом положи паспорт. Каталог без паспорта индекс считает сиротой.

## 3. Паспорт

Блок в первых строках `AGENTS.md` (или `CLAUDE.md`, если проект на нём):

```
<!-- passport
key: apl
parent: alfa
planning: team-work/alfa/apl
status: active
about: плагин Jira «Руководитель процесса»
-->
```

| Поле | Обязательно | Что |
|---|---|---|
| `key` | да | короткий ключ, им проект называют в журналах (`[apl]`) |
| `parent` | для подпроекта | `key` родителя; подпроект обязан лежать внутри него |
| `planning` | да, если есть | путь от `~/projects` |
| `status` | да | `active` · `paused` · `archive` |
| `about` | нет | одна фраза |

Комментарий HTML: в отрисованном markdown не виден, агент видит его, когда
читает инструкции проекта, скрипт разбирает.

## 4. Рабочие ветки (worktree)

- **Место одно:** `<репо>/.worktrees/<ветка>/`. Имя каталога = имя ветки.
  Никогда — в корне `~/projects`, рядом с репо, в `/tmp` (теряется при
  перезагрузке вместе с незакоммиченной работой).
- **Создаёт и снимает только `wt`** (`~/agent-os/bin/wt.sh`):
  `wt new epic-036` · `wt done epic-036` · `wt list`.
  `wt new` сам пишет `/.worktrees/` в `.git/info/exclude` — каталог не
  попадает в `git status` и в поиск (`rg` уважает исключения).
- **Имя ветки — по эпику:** `epic-036`, `epic-036-rating`; для бага `bug-012`.
  Каталог `apl-epic034` с веткой `epic-040` внутри — ровно то, чего больше не бывает.
- **Снимает тот, кто влил.** Влил ветку в ствол — в том же шаге `wt done`.
  `wt done` откажет, если ветка не влита или в ней незакоммиченное — это
  предохранитель, а не помеха: обходить его `git worktree remove --force` нельзя.
- **Эпик с живым worktree не закрыт.** Пункт «worktree снят» — в DoD шаблона
  эпика и в чек-листе resolve.
- Ствол — ветка, на которой стоит основной каталог репо (`main`, у Detective-OS
  `ds`). Основной каталог на другую ветку не переключают: это общее дерево.

## 5. Снимки, бэкапы, временное

- **Снимок «на всякий случай»** (перед переездом, перед правкой `.bashrc`) —
  в `~/backups/<дата>-<что>/` или `.tar.gz`, и строка в журнале: что, зачем,
  когда можно удалить. Не рядом с оригиналом, не в `~`.
- **Замороженное и сироты** — `~/projects/_archive/<дата>-<что>/`.
- **Временное агента** — scratchpad сессии или `mktemp -d`, и убрать за собой.
  Не в `~/projects`, не в `~`.

## 6. Индекс и сторож

`~/agent-os/bin/projects-index.py`:

| Вызов | Что |
|---|---|
| без флагов | список нарушений, ничего не пишет |
| `--summary` | одна строка; её печатает хук старта смены |
| `--write` | пересобрать `~/projects/INDEX.md` |
| `--strict` | код 1 при нарушениях (для проверок в скриптах) |

Ловит: каталог без паспорта, worktree не на месте, влитой worktree, мёртвый
worktree, подпроект вне родителя, вложенный репо без исключения в родителе,
симлинк из `~/projects` наружу, лишнее в `~` (включая `*.bak*`).

**Строка «беспорядок: N» на пороге — сигнал, не запрет.** Свои нарушения
(ветку, которую ты влил; каталог, который ты создал) разбираешь до работы.
Чужие — не трогаешь, а пишешь владельцу одной строкой.

`INDEX.md` пересобирается после любого изменения раскладки (новый проект,
снятая ветка, переезд). Два ручных реестра проектов не ведутся: таблица в
инструкциях заменяется ссылкой на `INDEX.md`.

## 7. Переезд каталога

- Только когда в нём **нет живой сессии** (порог смены показывает, кто где).
- worktree двигают `git worktree move`, не `mv`: иначе git теряет связь.
- До переезда — `rg` по старому пути в инструкциях, скиллах, хуках, `.bashrc`,
  скриптах; список правок готов заранее, правятся в том же заходе.
- После — `projects-index.py --write` и строка в журнале.
