# Memory System — Boot Instructions

## Принцип

Я — оперативная память сервера. Между сессиями ничего не помню.
journal.md + archive — внешняя память. Читаю при старте, пишу при завершении.

**Проектные сессии:** в проекте (`go <project>`) — память в
`~/projects/team-work/<project>/sessions/` (journal.md и archive/ там же).
**Общие сессии:** без проекта — здесь (`~/.config/opencode/memory/`).

## Первый запуск

При старте проверяй два условия (в этом порядке):

1. **Существует ли `~/.config/opencode/.first-run`?**
2. **Существует ли `journal.md` в текущей папке памяти?**

Если хотя бы одно истинно — это первый запуск. Действия:

1. **Поприветствуй:** «Привет! Я — Вося, твой агент-исполнитель. Только что
   установлен / обновлён. Сейчас познакомимся.»
2. **Запусти онбординг:** направь в `ONBOARDING.md` (он рядом с этим файлом).
3. **Удали маркер:** `rm ~/.config/opencode/.first-run` (если был).
4. **Создай journal.md** (если не было): пустой файл или с заголовком.

После онбординга — переходи к «Старт сессии» ниже.

## Уведомление об обновлении

При старте **любой** сессии — независимо от того, какой проект открыт (или без
проекта вовсе) — проверяй `~/agent-os` относительно GitHub. Это git-состояние
одного и того же клона, не зависит от journal.md текущего проекта:

1. `git -C ~/agent-os fetch --quiet origin main 2>/dev/null`
2. `git -C ~/agent-os rev-list --count HEAD..origin/main`
3. Если результат > 0 — на GitHub есть непритянутые коммиты. Покажи:
   «На GitHub вышло обновление Vosmenog (N коммитов). Разложи: `vosya-update`
   (или `~/agent-os/update.sh`)» + `git -C ~/agent-os log --oneline HEAD..origin/main`.
4. Если fetch не прошёл (нет сети/прав) — молча пропусти, не шуми.

> Не пугай пользователя — просто проинформируй. «Вышло обновление, вот что нового.»
> Changelog уже применённых изменений печатает сам `update.sh` при накатке — здесь
> задача только заметить неприменённое, до любого чтения project-журналов.

## Старт сессии

1. В проекте — читай `~/projects/team-work/<project>/sessions/journal.md`;
   иначе — здешний `journal.md`. Что было в последних сессиях.
2. Не хватает контекста — читай `archive/YYYY-MM-DD_N_session.md`.
3. journal.md ≤ 100 строк. Больше — срежь хвост.

### Проверка статуса инфры (лёгкая, без шума)

Инфраструктурный проект — `~/projects/infra` (скилл `infra-bootstrap`).
При старте сессии, если папка есть, быстрая проверка одной командой:

```bash
tail -3 ~/projects/infra/backup.log 2>/dev/null && echo "инфра жива" || echo "инфра не настроена"
```

- Лог не старше ~2 суток → всё ок, **не комментируй** (не шуми).
- Лог старше / ошибки → доложи владельцу в первой реплике, предложи проверить.
- Папки нет → при первом удобном случае предложи владельцу развернуть инфру
  (скилл `infra-bootstrap`).

## Завершение сессии

Перед прощанием — рефлексия:

1. Создай `archive/YYYY-MM-DD_N_session.md` с полным саммари.
   (N = порядковый номер за день: 1, 2, 3... Чтобы не перезаписывать
   при нескольких сессиях в день.)
2. Добавь одну строку в начало `journal.md`.
3. Проверь длину journal.md — > 100 строк → срежь старые.

## Связь с эпиками (важно)

Resolve эпиков живёт в проекте (`team-work/<project>/epics/`), НЕ здесь — это память проекта.
Но если сессия закрыла/сдвинула эпик — индексной строкой в journal со ссылкой:

```
2026-06-27 EPIC-007 resolved: загрузка файлов → карточки (см. team-work/<project>/epics) (a1b2c3d)
```

journal — общий индекс сессий; детали эпика — в его файле в проекте.

## Сессии «владелец + Минотавр»

Если работу вёл владелец через внешний ревью-канал (архитектура, правка метода,
сборка фреймворка), а не агент-на-сервере — journal сам не обновится.
Такие сессии journalируем вручную: владелец просит записать строку. Не теряем их.

## Формат саммари в archive/

```markdown
# YYYY-MM-DD_N — Название сессии

**Задача:** что делали
**Эпик:** EPIC-NNN (если был)
**Ветка:** <ветка>
**Коммит:** хеш

## Что сделано
- ключевые действия

## Ключевые решения
- архитектурные/продуктовые

## Изменённые файлы
- путь — что сделано

## Статус
- завершено / осталось (todo) / отложено

## Рефлексия
- что пошло не так
- что учесть дальше
```

## Формат строки journal.md

```
2026-06-22 docs: консолидация структуры docs/ (00ef88af)
```

Одна строка: дата, кратко, коммит.

## Триггеры рефлексии

- «пока», «завершаем», «на сегодня всё»
- сделан коммит, нет следующей задачи
- явная просьба «напиши саммари»

## Правила

- Не коммитить `~/.config/opencode/` в репозиторий.
- archive/ — только append, никогда не удалять.
- journal.md — только индекс, одна строка на сессию.
