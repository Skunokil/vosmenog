# user-profile.md — личные уточнения и уровень доверия

> Профиль пользователя фреймворка Vosmenog. Живёт в `~/.config/opencode/memory/`,
> защищён от затирания при обновлении (не в cp-списке `update.sh`, раскладывается
> по журнальному паттерну: если есть — не трогаю).
>
> **Не переопределяет METHOD.md.** Профиль делает две вещи:
> (а) уточняет рекон (Правило 1) — чем реконить, какие живые источники;
> (б) выставляет уровень доверия — ось, регулирующую частоту остановок и объяснений.
> Базовые стопы и принципы метода — в `~/agent-os/METHOD.md`, они не отменяются
> профилем ни при каких настройках.
>
> Уровень доверия работает по правилу `min`: итоговый уровень = строже (минимум)
> из профиля и опционального слота в `AGENTS.md` проекта. Проект может только
> ужесточить, не ослабить. Нет слота в AGENTS.md → берётся профиль.

---

## 1. Проектные уточнения рекона

Уточнения к Правилу 1 (Рекон перед правкой): какие инструменты/источники использовать
по умолчанию, какие живые системы спрашивать.

```yaml
# Пример:
# recon_tools:
#   - grep -n
#   - information_schema (БД)
# live_sources:
#   - http://localhost:8080/api/docs
```

## 2. Уровень доверия

Ось доверия — единый регулятор над Правилами 3/4/5/6 (go-гейт, итерации,
верификация, коммиты). Определяет частоту остановок и объяснений, **не снимает
барьеры**. На всех уровнях стоят: периметр (`external_directory`), три стопа,
`git push*: deny`.

Выбери один уровень, раскомментируй:

```yaml
# trust_level: обучающий     # объясняет каждую команду до ввода; согласует всё, включая рекон
# trust_level: средний       # рекон/чтение свободно, отчёт → согласование; каждая изменяющая
                             # команда согласуется; без объяснений
# trust_level: продвинутый   # короткие редкие объяснения; согласуется только принципиальное
                             # (там, где нужен бэкап/возможность отката)
```

> **Автоматика отсутствует** в списке уровней. Потолок сейчас — «продвинутый».
> Открытие автоматики — отдельным решением, не через профиль.
